# DEVIATIONS.md — осознанные отличия от оригинала

Все отличия ниже либо вынужденные (платформа/язык), либо улучшения,
не меняющие результат ёфикации на golden-корпусе. Паритет проверяется
тестами `tests/test_golden.cpp` (24 пары «файл × политика») и
`tools/golden.py` (Python-оракул логики оригинала).

## 1. Ядро ёфикации

1. **Ответ `skip` в запросе о неоднозначности** (`AskAnswer::skip`) —
   в оригинале такого ответа нет (есть «Е», «Ё», «Все на е», «Все на ё»,
   «Отмена»). Используется только CLI-политикой `--on-ambiguous=skip`
   (по умолчанию вне TTY): слово не меняется, обработка продолжается,
   счётчик увеличивается. GUI-панель ответ не показывает.
2. **Учёт исхода по словоформе** (`note_outcome`) заменяет
   `AddToStat`; сравнение форм идёт в CP1251 по предвычисленным
   ключам вместо декодирования — результат счётчиков
   Ye2Ye/Ye2Yo/Yo2Ye/Yo2Yo идентичен.
3. **Контекст РВ собирается через CRLF** только если окно выходит за
   пределы строки; внутри строки берётся срез самой строки. Содержимое
   контекста и границы окна совпадают с `GetContext` оригинала
   (golden-тесты покрывают оба случая).
4. **`\b`/`\B` внутри пользовательского шаблона** — если появятся в
   новом словаре, граница будет ASCII-шной (RE2), а не кириллической.
   В поставке `yo_regexpr.dat` таких правил нет (аудит: 0 вхождений,
   см. FORMATS.md §7).
5. **`\x{A0}` в `\s`** транслируется в `\xa0` (RE2 понимает оба
   варианта; результат идентичен).
6. **Порядок байтов в `DetectEncoding`** восстановлен как в оригинале
   (Lo, Hi) — без этого не распознавался `<?xml encoding=...?>`.
7. **Замена ё↔е выполняется «на месте»** (символы равной длины), поэтому
   смещения в строке не сдвигаются; оригинал перерисовывал фрагмент
   RichEdit. Для CLI/GUI это наблюдаемо только по скорости.

## 2. Форматы

1. `yox.dat` и `yo_regexpr.dat` читаются без конвертации; запись
   (этап 5, редактор словарей) — CP1251 + CRLF, порядок и `?`
   сохраняются.
2. `yo.ini` — гибрид: файл рядом с exe (portable), иначе
   `%APPDATA%\Yo\yo.ini`; ключи оригинала читаются и мигрируют.
   Первый запуск с незаписываемым каталогом: одноразовая миграция
   с уведомлением (условие §12.5).
3. Бинарный кэш индекса словаря — новый файл в
   `%LOCALAPPDATA%\Yo\cache` (этап 2 его не создаёт: индекс строится
   в памяти за ~100 мс на 140 324 слова).
4. `regexpr.log` — формат оригинала сохранён (`--regex-log`).

## 3. CLI (`yo-cli`)

1. Это unix-фильтр: результат — в stdout, отчёты/прогресс — в stderr.
   Оригинал — GUI-приложение.
2. Коды возврата: 0 — успех, 1 — ошибка, 2 — остались неразрешённые
   неоднозначности (`--on-ambiguous=fail`), 3 — прервано.
3. `--in-place` пишет атомарно (временный файл + переименование),
   опционально `.bak`; кодировка, BOM и переводы строк сохраняются.

## 4. Производительность (внутренние улучшения, результат тот же)

1. Поиск словоформы идёт через хеш-таблицу по нормализованному
   (е≡ё, нижний регистр) ключу с проверкой длины/байтов. Если в словаре
   есть совпадающие нормализованные ключи (в `yox.dat` — 9 групп),
   для этих ключей работает точная копия двоичного поиска оригинала,
   чтобы выбор записи не изменился.
2. Для словаря регулярных выражений дополнительно строится
   `re2::RE2::Set` (предфильтр кандидатов); порядок применения правил
   прежний.
3. Горячий путь ёфикации не выделяет память на слово: словоформы
   словаря декодируются один раз при загрузке в общий пул, статистика
   сравнивает ключи CP1251, буферы контекста/UTF-8 переиспользуются.

Ни одно из этих улучшений не меняет выводимый текст, порядок
запросов и статистику — это проверяется golden-тестами.

## Этап 3: GUI-редактор

- **Моноширинный шрифт.** MVP рисует текст моноширинным шрифтом
  (Cascadia Mono → Consolas → Courier New). Оригинал использовал RichEdit
  с пропорциональным шрифтом; раскладка пропорционального текста
  (измерение через DirectWrite, кэш ширин) — отдельный этап.
- **Атомарное сохранение.** Файл пишется в `<имя>.yo-tmp` и заменяется
  через `rename`, как `--in-place` в CLI. Оригинал писал напрямую.
- **EOL сохраняются как есть.** Mixed-файл при сохранении остаётся
  mixed: у каждой строки пишется её исходный EOL (оригинал нормализовал
  к CRLF). Вставка Enter использует доминирующий стиль файла.
- **Поиск в MVP** — точная подстрока (регистрозависимая), без опций
  «слово целиком»/«regex»; эти опции появятся вместе с полной ёфикацией
  (этап 4), regex-поиск переиспользует словарь РВ ядра.
- **RTF** открывается только для чтения: конвертера RTF→текст в ядре нет
  (в оригинале — RichEdit, читавший RTF).
- **Строка запуска** принимает один путь (как `yo-cli`), без параметров
  открытия на позицию/кодировку.
- **Вопросы ёфикации решаются «Ё»** до появления AskPanel: движку
  передаётся ответ «всегда Ё», поэтому неоднозначные слова сразу
  получают ё. В оригинале на этом месте открывалась панель с кнопками
  Е/Ё/Всегда Е/Всегда Ё/Откат/Прервать.
- **Отмена — по одной правке** (символ, вставка, удаление). Группировка
  «слово»/«абзац» появится вместе с ёфикацией (этап 4), где группы нужны.
- **Файл, открытый через mmap, остаётся отображённым после сохранения**:
  на диск пишется новый файл (атомарная замена), буфер продолжает жить
  на старом отображении до закрытия документа. Данные при этом верные.
