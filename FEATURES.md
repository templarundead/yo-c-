## 1. Назначение и состав

YOL — ёфикатор русских текстов: находит слова с `е`/`Е`, для которых в
словаре есть форма с `ё`/`Ё`, и заменяет `е`→`ё` (и наоборот при проверке
уже имеющихся `ё`). Работает построчно поверх RichEdit, словари — два
текстовых файла (см. FORMATS.md). Полная версия YO (с редактором словарей
и морфологией) заброшена; YOL — её «лайт»-вариант без этих модулей, но с
остатками их кода (см. §11).

Состав программы (`yol.dpr`): `MainForm` (создаётся первым), `AboutForm`,
`InputForm`, `FilePropForm`, `OptionsForm`. Инициализация: `InitData`
(каталоги, ini, таблицы отката, меню выключены), затем `Application.Run`;
загрузка словарей и файла из командной строки — отложенно в `OnIdle`
(`LoadAll`), чтобы окно появилось сразу.

### 2.2. Панель запроса (AskPanel)

Панель внизу окна (`alBottom`, высота 119 px в DFM). Содержимое:

- `reAskText` — read-only RichEdit с контекстом фразы (см. §4.4);
- `lCaption` — заголовок: «Выберите верный вариант» (обычный случай),
  «Вероятно, здесь должна быть "Ё"» (`WrongYe`), «Вероятно, здесь должна
  быть "Е"» (`WrongYo`), «Странное расположение "Ё"» (`ReplacedYo`);
  цвет заголовка красный при `WrongYe/WrongYo`, иначе тёмно-синий;
- Кнопки: `bYe` «Е (&1)», `bYo` «Ё (&2)», `bYeAll` «Всегда Е (&3)»,
  `bYoAll` «Всегда Ё (&4)», `bUndo` «Откат …» (подпись — `UndoCaption`,
  см. §4.6), `bCancel` «Прервать (Esc)» (`Cancel=True`, т.е. Esc = Отмена).
  `bYeAll/bYoAll` выключены при `WrongYo` (нельзя «всегда» для
  неправильного ё);
- Горячие клавиши кнопок 1–4 берутся из ini `ButtonHotKeys` (по умолчанию
  `1234`), переназначаются правым кликом по кнопке (`RedefineKey`:
  скрытый `TMaskEdit` с маской `A`, Enter — принять, Esc — отмена,
  дубликаты запрещены — `SetButtonHotKey` молча игнорирует занятую
  клавишу). Сохраняются в ini;
- Фокус при показе: `bYe`, если `ToFocusFirst`, иначе `bYo`;
- Фон панели: `clAskPanelActive = $FFC0C0` (розовый) при активном запросе,
  `clAskPanelPassive = $C0C0FF` (голубой) в режиме ожидания
  («Подождите или нажмите Esc») — этот режим включается на всё время
  ёфикации (`SetAskPanelView(False)`), активный — только на момент запроса.

### 2.3. Статусбар

Две панели: [0] — `строка:столбец (всего строк)` (`UpdateCursorPosition`,
1-based строка, столбец в символах WideChar), [1] — информационная строка:
во время загрузки словаря/файла — прогресс (`Загрузка словаря …: N%`),
во время ёфикации — статистика (§4.7). Хинт панели 1 (`StatusBarHint`)
расшифровывает поля статистики. Тулбар-хинт: «Дважды щёлкните здесь для
настройки панели инструментов».

## 3. Редактор

- Контрол: `TRichEditU` — наследник `TGsvUnicodeRichEdit` (обёртка над
  стандартным RichEdit с `EM_*`-сообщениями, `WideText`, `EM_SETCHARFORMAT`
  для цветов). `PlainText=True`, `HideSelection=False`, скроллбары оба,
  `WordWrap` управляется опцией, шрифт по умолчанию Courier New 10
  (charset 1 = DEFAULT_CHARSET). `MaxLength = $7FFFFFF0`.
- Практические ограничения RichEdit (важно для паритета и для обоснования
  замены, см. ARCHITECTURE.md): весь текст в памяти как UTF-16,
  построчный доступ `Lines[i]` через `EM_EXLINEFROMCHAR/EM_LINEINDEX`
  (дорого при больших файлах), форматирование/подсветка на каждый символ,
  UTF-8 обрабатывается «очень медленно» (предупреждение `msgUTF8Warning`
  при открытии UTF-8, отключается на сессию после первого согласия).
- Переводы строк: RichEdit нормализует всё к CRLF при загрузке/сохранении
  (исходные LF/CR не сохраняются). При сохранении в UTF-8 всегда пишется
  BOM; в UTF-16LE — BOM; UTF-16BE не поддерживается (только предупреждение
  `msgUTF16BE` при открытии, файл всё равно читается как ANSI и даёт кракозябры).
- Ручное редактирование: любой `OnKeyPress` в редакторе сбрасывает таблицу
  отката и список `YYPos` (`EditorKeyPress` → `ClearUndo` + `ClearYYPos`).
  `OnChange` выставляет `Edited=True` (кроме изменений во время ёфикации,
  где `YoRunning=True` подавляет `SetControls`).
- Закрытие/открытие: `CanBeClosed` спрашивает «Файл был изменён. Сохранить
  изменения?» (Yes/No/Cancel) только если `ToConfirmClose=True`; иначе
  молча теряет изменения. Заголовок окна — имя файла + ` *` при `Edited`
  (`SetCaptionAsterix`).

## 4. Ёфикация — ядро

### 4.1. Режимы запуска

- `Yobegin1` (Ctrl+F9): `DoYoficate(0,1)` — с начала текста.
- `Yopos1` (F9): `DoYoficate(LineN,PosN)` от текущей позиции курсора
  (строка/столбец из `SelStart`).
- Отдельного режима «только выделение» в оригинале **нет**: выделение
  игнорируется, ёфикация идёт от курсора (начало выделения, если курсор
  там) до конца текста. Требование ТЗ «от выделения» — новое (§12).
- `DoYoficate`: очищает откат, показывает AskPanel в пассивном виде,
  блокирует меню, ставит `RunTime0=Now`, затем цикл
  `repeat Yoficate(...); if ToMakeUndo then MakeUndo + перечитать позицию
  until not ToMakeUndo` (см. §4.6 про «Откат»). В конце — пассивная панель,
  разблокировка меню, фокус в редактор. Во время ёфикации нельзя
  максимизировать/закрыть окно (`NewMainFormWinProc` глотает
  `SC_MAXIMIZE/SC_CLOSE`), клики по редактору игнорируются
  (`NewEditorWinProc`).

### 4.2. Токенизация и проход по тексту (`Yoficate`)

- Проход — по строкам (`Lines[i]`), внутри строки — посимвольно.
  Слово = максимальный непрерывный отрезок символов `IsAlpha`, где
  `IsAlpha(c) = (c in 'А'..'Я','Ё') or (c in 'а'..'я','ё')` — **только
  кириллица** (байты CP1251; латиница, цифры, дефис, апостроф — разделители).
  `MySpaceChars = ' ' #9 #10 #13 #12 #160` (пробел, TAB, LF, CR, FF, NBSP).
- Слово обрабатывается, только если `Length>1` и содержит `е/Е/ё/Ё`
  (`IsYeYoIn`). Слова из одной буквы («о», «с», «в»…) никогда не меняются.
- `BrokenWord`: если стартовая позиция находится внутри слова
  (`PosN0<>1` и символы с обеих сторон — буквы), первое слово пропускается
  (нельзя ёфицировать слово, начало которого не видно).
- `FBFormat=True`: строка обрезается перед `<BINARY` (поиск
  `UpperCase(s)` на `<BINARY`); проход останавливается на строке с бинарным
  блоком (`BinaryFound`). Это поддержка FB2 (бинарные вложения книг).
- После каждого слова: `ToCancel := IsEsc` (`GetAsyncKeyState(VK_ESCAPE)`).
  `ClearEsc` перед стартом — busy-loop `while IsEsc do;` (ждёт отпускания Esc).
- Накопитель `cNotWord` — символы-разделители перед словом (нужен для
  распознавания сокращений/ноготочий, §4.3). После слова сбрасывается
  в `' '` (в конце строки — тоже `' '`, с комментарием «? зачем-то нужно»).

### 4.3. Сокращения, многоточия, заглавные (`CheckWordEx`)

Перед `CheckWord` вычисляются два флага (только если соответствующие опции
включены):

- `IsItAbbreviation(c, LineN, PosN)`: если разделитель после слова — `'.'`,
  сканирует вперёд (через пробелы и пустые строки) до первого
  непробельного символа; если он строчный (`IsLower`) — это сокращение
  («т.д. далее» → слово перед точкой считается сокращением).
- `IsItEllipsis(c, LineN, PosN)`: если с позиции разделителя строка
  начинается с `...` или `…` — слово оборвано многоточием.
- `ToCheckAbbreviation = ToConfirmAbbr and IsItAbbreviation`,
  `ToCheckEllipsis = ToConfirmEllipsis and IsItEllipsis`.
  Оба форсируют запрос к пользователю (см. §4.4), если для слова есть замена.

### 4.4. Выбор замены (`SelectWord` + `FindReplacement`)

Вход: `cWord` (слово из текста, с исходным регистром), `Idx` (абсолютная
позиция в тексте). Выход: `newWord` ('' = без замены) + `ToCancel`,
`DicWordIndex`, `WrongYo`.

1. `Word1 := ToYe(cWord)` (все `ё→е`, `Ё→Е`, регистр сохранён).
2. `Word2 := FindReplacement(Word1)`: бинарный поиск `Word1` в `Dic.Ye`
   через `FindInStringsUL` — сначала `RestLowerCase(Word1)` (первая буква
   как есть, остальные строчные), если не найдено — `LC(Word1)` (всё
   строчное). Сравнение `Cmp`: сначала `LC`-сравнение (без учёта регистра),
   при равенстве — побайтовое сравнение исходных строк (см. FORMATS.md §1).
   Если найдено: `Word2 = Dic.Yo[Index]` (форма с ё, с регистром словаря),
   `Always = UserSel[Index]<>0`; если `Always` — `ToAsk=False`,
   `WordToFocusN=UserSel[Index]` (1=Е, 2=Ё); иначе
   `ToAsk = WordsAsk[Index]<>0` (маркер `?` в словаре) и
   `WordToFocusN = WordsAnswer[Index]` (последний выбор пользователя)
   или 2, если выбора ещё не было. Если не найдено: `Word2=''`,
   `WordToFocusN=1`.
3. Форсирование запроса: `ToAsk := ToAsk or (Word2<>'' and
   ToCheckAbbreviation) or (Word2<>'' and ToCheckEllipsis) or
   (Word2<>'' and ToConfirmCap and IsUpper(cWord[1]) and not Always)`.
   Т.е. сокращения, оборванные слова и слова с заглавной (имена собственные)
   спрашиваются, если опция включена.
4. `IsYocWord := IsYoIn(cWord)` (в тексте уже есть ё).
   `WrongYo := IsYocWord and (LC(Word2)<>LC(cWord))` — в тексте ё, а словарь
   говорит иначе (или слова нет: `Word2=''` тоже даёт `WrongYo=True`).
   `ReplacedYo := WrongYo and (Word2<>'')`.
   `WrongYe := not IsYocWord and (LC(Word1)=LC(cWord)) and not ToAsk and
   (WordToFocusN=2)` — «вероятно, здесь должна быть Ё» (только для подписи
   панели; на логику не влияет, кроме заголовка).
   Если `ReplacedYo`, то `Word1 := CopyCase(Word2, cWord)` (варианты меняются
   местами: «Е-вариант» становится словарной формой).
   Если `(Word2='' and IsYocWord) or ReplacedYo`, то `Word2 := cWord`
   (вариант «Ё» = как в тексте). Затем `Word2 := CopyCase(Word2, cWord)`.
   `CopyCase(w, wCase)`: для каждой позиции `i <= min(len)`, если
   `wCase[i]` заглавная — `w[i]` приводится к верхнему регистру
   (`AnsiUpperCase`). Регистр переносится **по позициям**, не по буквам:
   если длины различаются (словарь и текст разной длины — бывает при
   `WrongYo`), хвост длиннейшего не трогается.
5. `VarOnly` (только интерактивные): если `VarOnly and not WrongYo` —
   пропустить без запроса (`Result=''`).
6. Regex-консультация: если `RegExprs and ToAsk` — `LookInRegExps`
   (§4.4.1). Если правило нашло ответ — `ToAsk=False`,
   `WordToFocusN=WordN` (1 или 2).
7. `NoVarOnly` (только беспроблемные): если `NoVarOnly` — пропустить
   (даже если regex уже нашёл ответ — проверка стоит после regex!).
8. `WrongYo`: если `NoVarOnly` — пропустить; иначе `ToAsk=True`
   (неправильное ё **никогда** не меняется без запроса).
9. `AlwaysAsk`: если `AlwaysAsk and Word2<>''` — `ToAsk=True`.
10. Если `ToAsk` — показ AskPanel (`AskForSelection`): контекст
    `FindContext` (см. ниже), фокус по `ToFocusFirst`:
    `ToFocusFirst := (WordToFocusN<>0 and ProposeLast and not WrongYo)
    ? (WordToFocusN=1) : (not IsYoIn(cWord) or WrongYo)`.
    Ответы: `mrYe/mrYo` (Е/Ё), `mrYeAll/mrYoAll` (Всегда Е/Ё — записывают
    `UserSel[DicWordIndex]=1/2`, включают пункт «Сбросить», затем
    понижаются до `mrYe/mrYo`), `mrUndo` (Откат — `ToMakeUndo=True`,
    ответ превращается в `mrCancel`), `mrCancel` (Прервать — стоп всего
    прохода). При `WordToFocusN>0` обновляется
    `WordsAnswer[DicWordIndex]` (запоминание последнего выбора).
    `WasAsk=True` для всех ответов, кроме... — выставляется всегда после
    панели (важно для отката, §4.5).
11. Результат: `WordToFocusN=1 → Word1`, `2 → Word2`, иначе
    `ToCancel=True` (стоп). Если `Result=cWord` — возвращается `''`
    (без замены, но слово засчитывается в статистику как проверенное).

Контекст панели (`FindContext`): отрезок текста вокруг слова, длина —
`reAskText.Width / ширина('x')` символов, по половине в каждую сторону,
переводы строк заменены пробелами. Слово выделяется красным жирным.
(Для regex-консультации используется другой контекст — `GetContext`,
см. FORMATS.md §2: 5 слов, `WordsBufferLength=5`.)

#### 4.4.1. Regex-консультация (`LookInRegExps`)

Вызывается только для неоднозначных слов. Для каждого правила по порядку
(см. FORMATS.md §2): матч по контексту из 5 слов; если подстановка е/ё
внутри целевого слова даёт `Word1` или `Word2` — ответ найден, первое
такое правило побеждает. Статистика: `Was[i]++`, `RELS.A++`,
`RELS.Changed/NotChanged` (сравнение `cWord` с выбранным вариантом);
если ни одно правило не подошло — `NoRELS++`. При `RegExprLog=True`
пишется в `regexpr.log` (формат — FORMATS.md §5).

### 4.5. Применение замены (`CheckWord` + `ChangeLetter`)

- `CheckWord`: если `IsYoIn(cWord) and not CheckYo` — слово с ё пропускается
  целиком (режим «не проверять уже имеющиеся ё»). Иначе `SelectWord`,
  статистика (§4.7), `AddToStat` (счётчики по словарю), `ChangeLetter`.
- `ChangeLetter(Idx, oldWord, newWord)`: для каждой позиции, где буквы
  различаются: если `WasAsk` — `AddUndo(Idx+k, …)`; выделение 1 символа,
  если `Mark` — цвет `clMark` (по умолчанию синий) + фон `clBackMark`
  (по умолчанию жёлтый, если `<>$FFFFFF`); замена символа; позиция
  `Idx+k+1` вставляется в отсортированный список `YYPos`
  (`PutToIntegerList`). Замены без запроса (автоматические) **не попадают**
  в откат и **не подсвечиваются** — только интерактивные.
- `Findyyfwd1/Findyyback1` (Ctrl+W/Ctrl+Q): линейный поиск по `YYPos`
  вперёд/назад от `SelStart`.
- `RemoveMarked1` (Shift+F10): `RemoveMarkedLetters` — весь текст
  перекрашивается в цвет шрифта/фон окна (снимает подсветку замен).

### 4.6. Откат (Undo)

- Таблица отката: параллельные списки `UndoP1` (позиция слова),
  `UndoP2` (позиция буквы), `UndoColor` (исходный цвет), `UndoLetter`
  (строка исходных букв), `UndoOldWord/UndoNewWord` (слова для подписи).
  Заполняется только для интерактивных замен (`WasAsk`).
- `MakeUndo`: снимает **последнюю** запись: восстанавливает букву и цвет,
  курсор на начало слова. Пункт меню `Undo1` (Ctrl+Z) показывает
  `UndoCaption`: `Откат "старое -> новое"` по последней записи.
- Кнопка «Откат» в AskPanel (`mrUndo`): не просто откат — `DoYoficate`
  после `MakeUndo` **перезапускает** `Yoficate` с текущей позиции
  (курсор после отката). Т.е. «Откат» = отменить последнюю замену и
  продолжить ёфикацию с этого места (пользователь может выбрать иначе).
- Многоуровневый undo в современном смысле (redo, откат ручных правок,
  откат автоматических замен) в оригинале **отсутствует** — см. §12.

### 4.7. Статистика

- Статусбар во время ёфикации (`ShowStatus`):
  `t=t1+t2  A=a1+a2  RE=r1+r2  REQ:%  E:%d  T:%0.2f  S:%d`, где
  `t` — всего проверено слов (`CheckedLS.A = Changed+NotChanged`),
  `A` — проверено с запросом (`AskedLS`, только `WasAsk`),
  `RE` — применений regex (`RELS.A = Changed+NotChanged`),
  `REQ` — эффективность regex `RELS.A/(RELS.A+NoRELS)*100%`,
  `E` — число неправильных ё (`WrongYoLS`),
  `T` — время в секундах от `RunTime0`, `S` — скорость (замен/сек).
  Счётчики **накапливаются** между запусками ёфикации (не сбрасываются
  при старте; сброс — только перезапуском программы; пункты
  `Clearstat1/Stat1` в `SetControls` ссылаются на несуществующие пункты
  меню — мёртвый код, §11).
- Счётчики по словарю (`AddToStat`): `Ye2Ye/Ye2Yo/Yo2Ye/Yo2Yo` — сколько раз
  каждое слово словаря встретилось в каждой форме. В YOL нигде не
  отображаются (остаток полной YO).
- Свойства файла (`CalculateFileProp`, `FilePropForm`, 8 строк):
  имя файла; формат (`UTF-8/UTF-16LE/UTF-16BE/ANSI` + `sgn` + `, rich text/
  plain text`); длина файла в байтах; длина текста в символах;
  число символов кириллицы (`IsAlpha`); число `е`; число `ё`;
  степень ёфикации: `Y = Round(nYo*1500/nYe)` (при `nYe=0`: 100, если
  `nYo>0`, иначе 0), подпись: 0 — «не ёфицировано», <75 — «возможно,
  ёфицировано не полностью», иначе — «возможно, ёфицировано».
  Формула `nYo*1500/nYe` — баг/квирк: при `nYo=nYe` даёт 150%
  (см. §13). Подсчёт — по `WideText` целиком, O(n).

## 5. Поиск

- `Find1` (Ctrl+F) — обычный поиск, `Findreg1` (Ctrl+R) — regex-поиск.
  Оба открывают один `TFindDialog` (модальный диалог Windows с опциями
  «С учётом регистра», «Слово целиком» — для regex слово целиком скрыто
  через `frHideWholeWord`). `FindAgain1` (F3) повторяет последний поиск
  без диалога; подпись меняется на «Найти РВ снова» для regex.
- Обычный поиск: `RichEdit.FindText/FindWideText` от `SelStart+SelLength`
  до конца, с `stWholeWord/stMatchCase` по опциям диалога. Найденное
  выделяется (`SelLength`), курсор — на начало. Поиск **только вперёд**,
  без зацикливания, без подсветки всех совпадений, без замены.
- Regex-поиск: `FindRegExpr` (`ModifierM/S/I=True`,
  `ModifierI = not MatchCase`, `SpaceChars/WordChars` как в словаре),
  `Exec(SelStart+SelLength+1)` по всему `WideText`, `MatchPos[0]-1`.
  Поддерживается тот же синтаксис TRegExpr (см. FORMATS.md §2).
- Хак с первым вызовом: `FindDialog1.Execute` первый раз срабатывает
  без показа формы, поэтому используется флаг `FindNextWasPressed`
  + `OnClose` для включения `Findagain1`.

## 6. Файлы, кодировки, диалоги

### 6.1. Типы текста (битовые флаги `tt*`)

`ttRTF=$01`, `ttUTF8=$02`, `ttUTF16LE=$04`, `ttUTF16BE=$08`,
`ttUTFsgn=$10` (есть BOM), `ttUTF16=LE|BE`, `ttUnicode=UTF8|UTF16`.
Индексы комбобокса диалога: `AnsiIndex=0`, `UTF8Index=1`, `UTF16Index=2`.

### 6.2. Автоопределение (`UnicodeTextType`, `RTFTextType`, `GetTextType`)

- `RTFTextType`: только по расширению `.RTF` (верхний регистр).
- `UnicodeTextType(FileName, Auto)`: читает первые `UTFLength=512` слов
  (по 2 байта, `file of word`), проверяет BOM (UTF-16LE/BE, UTF-8
  `EF BB BF`), ищет `encoding="utf-8"` в первых байтах (для FB2/XML),
  считает `u8` (байты `D0/D1` — кириллица в UTF-8), `u16h/u16l`
  (нули/`$04` в старшем/младшем байте — эвристика UTF-16LE/BE).
  При `Auto`: `u8>20 → UTF8`, иначе `u16h>=u16l and u16h>nu16h → UTF16LE`,
  `u16l>nu16l → UTF16BE`. При `Auto=False` эвристика не применяется,
  только BOM и `encoding="utf-8"`.
- `GetTextType(FileName, TextType)`: объединяет выбор диалога с авто:
  при `AutoUnicode=True` — `RTF | авто`; при `False` — выбор диалога
  + только BOM из авто (эвристика игнорируется).
- При открытии: UTF-16BE → только `Info(msgUTF16BE)` (файл всё равно
  грузится как ANSI); UTF-8 → предупреждение `msgUTF8Warning`
  (если не отключено в ini `Internal.UTF8Warning`).

### 6.3. Диалоги открытия/сохранения (`DialogEnc`)

Кастомный шаблон диалога (ресурс 131) с комбобоксом кодировки
(ANSI / UTF-8 / UTF-16, id 257). При открытии и `AutoUnicode=True`
комбобокс выключен (`EnableEncoding=False`). Фильтры открытия:
`Plain text|*.txt|Rich text|*.rtf|FictionBook text|*.fb2|All types|*.*`
(по умолчанию All types); сохранения: `Plain text|*.txt|Rich text|*.rtf`.
Выбор RTF определяется по `FilterIndex`, кодировка — по комбобоксу.
FB2 открывается как plain text (RichEdit читает XML как текст);
при ёфикации с `FBFormat` пропускаются `<binary>`-блоки (§4.2).

### 6.4. Загрузка/сохранение (`TRichEditU.LoadFromFile/SaveToFile`)

- Загрузка: `SF_TEXT` (+`SF_RTF` для RTF, +`SF_UNICODE` для UTF-16LE)
  через RichEdit; первый символ BOM (`$FEFF/$FFFE`) срезается;
  UTF-8 без BOM: `WideText := UTF8Decode(Text)` (двойное преобразование
  через ANSI — источник артефактов на не-CP1251 байтах).
- Сохранение: UTF-8 — `UTF8Encode` + ручная запись BOM `EF BB BF`
  (всегда с BOM, даже если исходник был без BOM); UTF-16LE — `SF_UNICODE`
  + BOM; ANSI — CP1251 через RichEdit; RTF — `SF_RTF`.
- Предупреждения о потерях (`SaveFileAs`): если было RTF, а стало plain,
  или было Unicode, а стало ANSI — `msgMayBeLost` («некоторые символы
  могут быть потеряны. Продолжить?»). Перезапись существующего файла —
  `msgRewrite`. Сохранение **неатомарное** (прямая запись RichEdit).
- Сохранение в исходной кодировке (`Save1`): `TextFileType` файла.
  После `SaveAs` новый тип/имя запоминаются, файл добавляется в MRU.

## 7. Последние файлы, drag-and-drop, командная строка

- MRU: до 9 файлов (`MaxFileNamesInList=9`) в меню Файл после разделителя
  `Openfile0`, хоткеи Ctrl+1…Ctrl+9. Хранится в ini `Files.Name1..9`
  (формат — FORMATS.md §3) + `LastFileN`. При переполнении список сдвигается
  (FIFO, не LRU: повторное открытие существующего файла не меняет порядок —
  `AddFileToList` выходит, если файл уже есть).
- Позиция курсора: `FileNamesPos` (абсолютный `SelStart`) запоминается при
  открытии/закрытии/переключении (`RememberFileNamesPos`, сравнение имён
  без учёта регистра `LC`) и восстанавливается при открытии
  (`GoAndShowPosition(GetFileNamesPos(s))`). Кодировка файла тоже хранится
  в MRU (`FileNamesTextType`) и используется при открытии из списка.
- `RecallLastFile=True` (по умолчанию): при старте открывается последний
  файл (`LastFileN` из ini) — но только если файл из командной строки не задан.
- Drag-and-drop: `WM_DROPFILES`, только первый файл (`DragQueryFile(...,0)`),
  с `CanBeClosed`-проверкой и автоопределением типа (`GetTextType(...,0)`).
- Командная строка: `ParamStr(1)` — имя текстового файла (только один
  аргумент, без ключей). Словари — только через ini/диалоги.
- `TextDirectory` (последний каталог) запоминается в ini и используется
  как `InitialDir` диалогов.

## 8. Настройки (OptionsForm)

Диалог с двумя вкладками («Ёфикация», «Редактор»), кнопки «Применить» (OK),
«Отменить», «Применить и запомнить» (Yes — пишет в ini через
`DefaultYoOptions`). Опции (`TOptions`, все — в ini, см. FORMATS.md §3):

Ёфикация: `CheckYo` (проверять уже имеющиеся ё), `NoVarOnly` (только
беспроблемные замены), `VarOnly` (только интерактивные), `AlwaysAsk`
(всегда спрашивать), `ToConfirmAbbr` (спрашивать для сокращений),
`ToConfirmCap` (спрашивать для имён собственных), `ToConfirmEllipsis`
(спрашивать для оборванных слов), `ProposeLast` (предлагать последний
вариант), `RegExprs` (использовать словарь regex; выключен, если словарь пуст),
`FBFormat` (учитывать формат FictionBook).

Редактор: `FastScroll` (быстрая прокрутка — не перематывать вьюпорт
к каждому слову при ёфикации), `Mark` (подсвечивать замены) + цвета
`clMark/clBackMark` (диалог цвета, превью в `SampleEditor`),
`WordWrap`, `LastFile` (запомнить последний файл), `ToConfirmClose`
(подтверждать закрытие), `AutoUnicode` (автоопределение Unicode),
`LinesBelow` (сколько строк держать под словом при запросе, по умолчанию 2),
шрифт редактора (имя/размер/charset, `FontDialog`), `ShowToolBar`.

Взаимные блокировки в диалоге: `AlwaysAsk` отключает три `ToConfirm*`;
`VarOnly` и `NoVarOnly` взаимоисключают друг друга; кнопки цветов
доступны только при `Mark`.

## 13. Известные баги и квирки оригинала (для golden-тестов)

1. `CalculateFileProp`: `Y=Round(nYo*1500/nYe)` — при равных `nYo=nYe`
   даёт 150%. При `nYe=0, nYo>0` — 100%.
2. `WriteIni` пишет `DefaultYoOptions`, а не текущие `YoOptions`:
   «Применить» (OK) в опциях действует только до перезапуска;
   сохраняется только «Применить и запомнить» (Yes) и геометрия окна.
3. `WordsBufferLength` читается из ini, но никогда не пишется
   («меняется только правкой файла»).
4. Бинарный поиск по словарю с дубликатами нормализованных форм
   (в `yox.dat` — 360 групп дублей, напр. фамилии `Аксенова/Аксёнова`):
   `FindInStrings` возвращает середину диапазона, т.е. произвольный
   дубль. Детерминированно при фиксированном словаре, но хрупко.
5. `SelectWord`: проверка `NoVarOnly` стоит **после** regex-консультации —
   regex-статистика (`RELS/NoRELS`) растёт даже в режиме `NoVarOnly`.
6. `ChangeLetter`/`YYPos`/`AddUndo` — только для `WasAsk`. Автоматические
   замены нельзя откатить и нельзя найти через Ctrl+W/Q.
7. `EditorKeyPress` сбрасывает откат и `YYPos` при любом нажатии клавиши
   в редакторе (включая стрелки? — `OnKeyPress` срабатывает только на
   символьных клавишах; навигация откат не сбрасывает).
8. `ClearEsc`: `while IsEsc do;` — busy-wait без `Sleep` (100% CPU,
   если Esc зажат).
9. `UnicodeTextType`: `s` накапливает первые ~1024 байта как `Char(w)+Char(h)`
   (младший/старший байты слова) — для UTF-16 это мусор, но поиск
   `encoding="utf-8"` всё равно работает для ASCII-префикса XML.
10. Загрузка UTF-8 без BOM через `UTF8Decode(Text)`: `Text` уже декодирован
    RichEdit как ANSI (CP1251), затем передекодирован как UTF-8 — байты
    вне CP1251/UTF-8 дают артефакты.
11. Сохранение UTF-8 всегда с BOM; сохранение UTF-16LE вставляет BOM
    в `WideText` и затем срезает его обратно (`Copy(WideText,2,…)`).
12. `Yoficate` читает `Lines[i]` на каждой итерации (RichEdit
    `EM_EXLINEFROMCHAR` + копирование строки) — квадратичная сложность
    на больших файлах; `GetContext`/`FindContext` — аналогично.
13. `FindInStrings` проверяет первый и последний элементы отдельно
    (оптимизация для частых слов в начале/конце словаря) — на результат
    не влияет, но влияет на скорость.
14. `IsItEllipsis`: `Copy(s, PosN, Min(3,…))` и `Pos('...',s)=1` — проверяет
    только начало среза; `…` — один символ (в CP1251 — байт `$85`? в коде
    это WideChar в RichEdit-контексте).
15. `ReadDic`: прогресс `Round(Lines*13.2/fs*100)` — магическая константа
    13.2 (средняя длина строки словаря в байтах с CRLF).
16. `AddFileToList`: FIFO без обновления порядка при повторном открытии;
    `RememberFileNamesPos` сравнивает имена через `LC` (без учёта регистра).
17. `OpenText` вызывает `SetWordWrap` с комментарием `? bad if >64K`
    (RichEdit-ограничение).
18. `TDialogEx.DoShow`: при открытии и `AutoUnicode` комбобокс кодировки
    выключен — пользователь не может переопределить автоопределение
    для открытия (только для сохранения).
19. `SaveFileAs`: предупреждение о потерях проверяет только
    RTF→plain и Unicode→ANSI, но не ANSI→UTF-8/UTF-16 и не потерю BOM.
20. `Cas(i,Mode)` для падежей числительных: Mode 1 — «а/ы/»,
    Mode 2 — «о/а/», Mode 3 — «е/я/й» (для «N слов/выражений»).
